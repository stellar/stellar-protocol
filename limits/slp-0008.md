## Summary

This proposal freezes the Stellar account entry that received funds drained from Mercado Bitcoin on November 2, 2026, using the frozen ledger key mechanism defined in [CAP-0077](../core/cap-0077.md). The freeze is applied through a network configuration upgrade.

## Background

On November 2, 2026, [wallets attributed to Mercado Bitcoin](https://www.coindesk.com/business/2026/11/02/brazil-s-mercado-bitcoin-halts-withdrawals-after-usd40-million-drained-across-10-chains), a Brazilian exchange, were drained across at least ten chains, including Stellar. Hypernative estimates total losses above $40M. The largest outflows occurred between 06:19 and 06:53 UTC, when wallets on every affected chain sent most of their funds to fresh attacker addresses.

On Stellar, about 6.7M XLM was moved to `GDXYRI6IONQA5YTGRLQ6O3FGJ2BWXPJTTQPUXFPSEXSRKBZLFKMZSOLP`, which Hypernative attributes to the attacker. The outflows were plain transfers signed with Mercado Bitcoin's keys. They were not an exploit of the Stellar protocol or of any smart contract. How the attacker obtained signing access is not yet known.

Mercado Bitcoin has asked that this account be frozen.

[CAP-0077](../core/cap-0077.md) introduced protocol support for freezing ledger entries through network configuration, and [SLP-0006](slp-0006.md) used it to freeze accounts tied to the YieldBlox exploit. This proposal uses the same mechanism for the account entries listed below.

## Goals Alignment

This proposal supports network safety and reliability by using the network configuration upgrade path defined in CAP-0077 to keep the stolen XLM from leaving the attacker's account while recovery efforts proceed.

The proposal is limited to a single account entry: the account that received the drained Mercado Bitcoin funds. As of 13:10 UTC on November 2, 2026, almost all of that XLM is still in that account.

## Proposed Settings

This proposal applies a `CONFIG_SETTING_FROZEN_LEDGER_KEYS_DELTA` configuration upgrade as defined by CAP-0077.

The `keysToFreeze` value contains the following account ledger key.

```
LedgerKey ACCOUNT GDXYRI6IONQA5YTGRLQ6O3FGJ2BWXPJTTQPUXFPSEXSRKBZLFKMZSOLP
```

The full base64 XDR encoded `ConfigSettingEntry` value is listed below.

```
AAAAEgAAAAEAAAAoAAAAAAAAAADviKPIc2AO4maK4edspk6Da70znB9LlfIl5RUHKyqZmQAAAAA=
```

The `keysToUnfreeze` value is empty. This proposal does not add any transaction hashes to `freezeBypassTxs`.

## Settings Change Rationale

### Freeze GDXYRI6IONQA5YTGRLQ6O3FGJ2BWXPJTTQPUXFPSEXSRKBZLFKMZSOLP

This account is identified by Hypernative as the attacker's Stellar address in the Mercado Bitcoin incident. It was created at 06:27 UTC on November 2, 2026 by `GDQE7YHNL7L7M664GJXU5VVEIBTYG44O3PHWVZCZJZQ2FDFO4S2XGAFE`, the Mercado Bitcoin wallet it then drained.

Transactions:

- Account created with 10 XLM by `GDQE7YHN` [c1d6d3c0e327613a6c777d440f5e9670e60a362efe672ec7f81fafc01d67c810](https://stellar.expert/explorer/public/tx/c1d6d3c0e327613a6c777d440f5e9670e60a362efe672ec7f81fafc01d67c810)
- 6,717,490 XLM payment from `GDQE7YHN` [869b6976c19eb51e41d266aa4b5945ad1a63719c8a4dc70e19e41181be898238](https://stellar.expert/explorer/public/tx/869b6976c19eb51e41d266aa4b5945ad1a63719c8a4dc70e19e41181be898238)
- 5,000 XLM sold on the DEX by the account itself, its first outbound activity [48c3935225e0fb7e5fbf2b4a32c31e69365c00fe4f25fc216e50ef565f421853](https://stellar.expert/explorer/public/tx/48c3935225e0fb7e5fbf2b4a32c31e69365c00fe4f25fc216e50ef565f421853)

As of 13:10 UTC on November 2, 2026, the account holds about 6,712,500 XLM. It has a single signer (its master key) and has not sent funds to any other account.

For additional information, see the [Hypernative detection report](https://app.hypernative.xyz/risk-insights/explore/I5OYW2PY55T3) and the [Mercado Bitcoin statement](https://x.com/MercadoBitcoin/status/2117239507263132056).

## Security and Operational Considerations

CAP-0077 allows account entries to be included in the frozen ledger key list. A transaction that accesses a frozen account entry is handled according to the validation and apply rules defined by CAP-0077.

The change can be reversed by a later network configuration upgrade that includes the account ledger key in `keysToUnfreeze`. This proposal does not define any bypass transactions, and does not address how funds might be returned to Mercado Bitcoin.
